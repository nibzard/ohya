# ohya trademark policy

"ohya"™, the ohya logo, and the elephant mark are trademarks of Niko. This
policy tells you how you can use them.

The MIT License gives you rights to the code. It does not give you rights to
the name or the logo. This policy does not limit your rights under the MIT
License. You can always fork, change, and distribute the code under a
different name.

## You can do these without permission

- Refer to the project by name, for example "works with ohya", "an
  integration for ohya", or "a fork of ohya". Use the name only as much as
  necessary to identify the project.
- Write about ohya in articles, talks, books, tutorials, and lists of tools.
- Distribute unmodified official releases or unmodified source code under the
  name ohya.
- Keep technical identifiers in a fork when a change would break
  compatibility. Examples are the `ohya` command name, the `~/.ohya`
  directory, configuration keys, protocol names, and the MCP server name.

## Forks and modified versions

If you distribute a modified version of ohya, you must:

- Give it a different name that is not confusingly similar to "ohya".
- Remove the ohya logo and the elephant mark.
- Not state or suggest that the ohya project made, approved, or supports it.

You can say that your project is based on ohya. You do not have to.

Private changes that you do not distribute are not limited by this policy.

## You cannot do these without written permission

- Use "ohya" or a confusingly similar name in the name of a product, service,
  company, domain, package, or social media account.
- Use the logo or the elephant mark. The brand files have their own license:
  see [`docs/assets/brand/LICENSE`](docs/assets/brand/LICENSE).
- Use the name or the logo in a way that suggests that the ohya project
  endorses you or your product.
- Sell merchandise with the name or the logo.
